## A. 菜单、最近复制、剪贴板面板彻底重做

重点检查：`Sources/Nexus/MenuPopoverView.swift`、`RecentPathRow.swift`、`AppState.swift`、`StatusItemController.swift`、`ClipboardShelfView.swift`、`ClipboardSourceAppBadge.swift`、`ClipboardMonitor.swift`、`ClipboardSourceAttribution.swift`。

1. 修复菜单控件未对齐：图标、标题、内容、按钮按统一网格、基线与间距排列；不要挤压/截断。恢复显式 **「最近复制的路径」** 列表或入口（与普通剪贴板记录分开），显示实际最近路径，支持一键复制路径。保留「上次拷贝」：点击其内容/行**直接复制对应路径到系统剪贴板**，不打开任何面板。
2. 「最近的剪贴板」菜单（含置顶记录）中，点击**任意一条记录直接把该条完整内容复制回 NSPasteboard**，**不能**触发 `onOpenClipboardShelf()`；仅独立的「打开剪贴板面板」按钮负责打开面板。文本、图片、文件 URL、富文本/可恢复的格式尽量原样恢复，而不是只复制预览标题；失败时明确提示。阻止 Nexus 自己的“再次复制”产生无限重复历史。
3. 剪贴板面板采用真正的 macOS 原生 SwiftUI/AppKit 响应式布局，不沿用当前拥挤/裁切视觉。首次打开、再次打开和不同显示器/缩放/窗口尺寸都不能出现用户反馈的默认尺寸过小、内容被压缩或裁掉。合理的最小尺寸、可调整尺寸、可滚动区域、网格自适应、文本换行/省略与明确的“展开详情”控制；记住用户主动调整的尺寸（在当前屏幕可见范围约束内）。卡片主操作为复制，详情/预览与粘贴到前台应用须显式、分离，不自动打开或自动粘贴。
4. 复制来源：可识别时仅显示 **应用图标 + 简短应用名**（例如 ChatGPT 图标 +「ChatGPT」），不显示「报告的来源名称」「前台应用（未验证）」「未知来源应用」等笨重字样，也不在显示时直接露出 Bundle ID。用 `NSWorkspace` 等解析名称/图标；解析不到时**省略来源标签**，不要捏造来源。检测时的前台应用只能标注为尽力推断，不得在数据层谎称已核实真实来源；可在详细说明中解释局限。兼顾语音辅助和深浅色模式。
5. 保留剪贴板搜索、置顶、收藏、分类、删除、快捷键与现有数据；避免破坏用户已有历史记录。

验收：点击最近剪贴板的文字、图片、文件记录→系统剪贴板恢复对应内容，面板不弹；点击「上次拷贝」→复制路径；「最近复制的路径」可见并可用；窗口缩放/重开无裁切；ChatGPT 来源显示其名称/图标（若能可靠解析）。

## B. 同步文件夹改为“复制内容原样存放”，不再只放待解析文件

重点追踪剪贴板历史持久化、用户选择的同步目录、`ClipboardCloudController.swift` 及现有文件同步/导出相关逻辑；区分「剪贴板同步文件夹」与统计数据库备份目录，不能把两个用途混为一谈。

- 用户**明确启用并授权**某个本地/iCloud Drive 文件夹后，将**实际复制的内容**作为用户可直接打开、使用的普通文件落到该目录，而不是只写供 Nexus 解析的 JSON、索引、数据库快照或引用清单：复制文件→完整原文件字节；复制目录→完整目录结构（权限允许时）；复制图像→可直接打开的图像文件、尽量保留原始编码；复制文本→完整文本文件；富文本尽可能保留格式。若某种系统剪贴板私有格式无法无损导出，清楚展示支持范围，而不是声称全格式原样。
- 取消**这一用户选择的文件夹镜像流程**中的 8 MB、64 KB 等人为阈值与截断；大文件采用流式/文件系统复制、后台异步队列、进度/取消、原子写入、冲突安全命名及真实磁盘空间/权限/云端可用性错误处理，不一次性将大文件载入内存。**“不限大小”指不设置人为文件大小门槛，不意味着超出实际可用空间仍能成功。**
- 对多次复制、重名、多个文件/目录、剪贴板类型变更、复制失败、重启、暂停/恢复和选择新文件夹做端到端验证；不静默丢失。仅在用户明确选择文件夹后写入，不擅自上传敏感剪贴板内容。现有 CloudKit CKAsset 附件同步与本地/iCloud Drive 普通文件夹镜像是两种独立机制：不要因为本要求就谎称 CloudKit 无限制或破坏现有云端兼容性。
- 镜像目录中优先让用户看到可直接使用的内容文件；必要的程序元数据应隔离于隐藏索引目录，不以元数据取代内容。既有历史与同步状态保持可迁移。

## C.「时间趋势」统计图表**重设计展示层**，不是微调旧图

重点：`Sources/Nexus/InputStatisticsView.swift`、现有 dashboard/聚合查询/统计存储；保留正确的实际数据与既有持久化。

- 原生 SwiftUI + Apple Charts；重新规划信息层级、留白、坐标轴、网格、图例、颜色、布局和小窗口适配。设计要达到可发布的 macOS 应用水准，支持深色/浅色。不接受仅换颜色、字体和尺寸。
- 时间横轴、事件数纵轴，多类型堆叠柱（鼠标、普通字符、滚轮、快捷键、功能键、修饰键）；可按时间粒度/范围切换，分桶边界和时区正确，事件不重不漏；少数据时也应可读，不要柱子全部挤到右缘或遮挡纵轴。
- 鼠标悬停展示时间段、分类值与总量；图例点击筛选类别；提供「总览／键盘／鼠标」或等效分组视图。滚轮事件量级大时允许单独指标/尺度，避免掩盖其他事件，并清楚标注单位与统计口径。适配空状态、稀疏数据、密集数据、长时间范围与窗口调整。
- 学习（**只读具体相关源码**）：https://github.com/SherlockGougou/MacKeyAnalyze （Dashboard/Aggregation/Analytics，路径变化则搜索）；https://github.com/NilCoalescing/Swift-Charts-examples （ChartAnnotationsOnHover）；https://github.com/willdale/SwiftUICharts （布局概念参考，勿无故引入依赖）。
- 测试：跨天/跨月/DST、分桶汇总、类别筛选、零值与异常峰值；在 macOS 上实际检查不同窗口尺寸。不能用测试假数据冒充真实统计展示验收。

## D. 键盘事件识别架构重构（含服务器和统计）

重点：`Sources/Nexus/InputMonitor.swift`、`NexusCore` 事件模型/统计聚合、`Sources/Nexus/InputStatisticsView.swift`、`Server/worker.js`、`Server/nexus_api.py` 及相关测试。

已知问题：目前普通按键默认成为 `character_total`，`shortcutKeys` 和 `shortcutName()` 只处理少量硬编码组合；服务端对 `ordinary`/`shortcut` 等实施固定白名单。不能只增加映射表而不修改模型/同步校验。

1. 建立可测试的通用物理键事件解析器：A–Z、0–9、主键盘与数字小键盘、标点、空格、导航键、Delete/Return/Tab/Escape、F1–F20（硬件存在且事件可观测时）、左右 Shift/Cmd/Opt/Ctrl、Caps Lock、Fn/Globe、媒体/亮度/音量/播放键。区分键码、键盘设备、按键按下/释放、修饰状态、长按/自动重复及最终显示名，避免多事件通道重复计数。
2. 任何有效组合都能通用解析：Shift/Command/Option/Control/Fn 与普通键及多修饰键，例如 `Shift+A`、`Shift+1`、`Cmd+1`、`Ctrl+Shift+A`、`Cmd+Shift+4`、`Fn+F1`（系统能提供时）。区别**观察到组合**、**实际输出字符**、**已识别的系统/应用快捷键功能**，不得把所有 Shift+普通输入误认为快捷键。
3. 使用虚拟键码 + 当前键盘布局解析可显示键名/字符，兼顾输入法切换、非美式布局、Option 组合、Caps Lock；不硬编码 Shift+1 必然是 !。支持识别已公开的系统/应用菜单快捷键、用户自定义映射和已知第三方配置；未能判定作用时仅显示组合键，支持用户自行命名，不能虚构触发的功能。
4. 设备与系统事件采用适当的 `CGEventTap`/`NSEvent`/`IOHIDManager` 等，仅使用公开且有权限的 API。Touch ID/保留事件/安全输入无法观察时如实说明。不要绕过 Secure Event Input/权限保护，默认不存储可重构输入内容的原始键序列、密码、验证码；单键频率等采用隐私保护的聚合口径，明确本地/云端授权差异。
5. 历史统计保留；数据模型/本地 SQLite/服务端校验/云端同步协议协调迁移，兼容旧 `character_total` 记录，避免重复计数。UI 提供可用的按键分类/组合统计与可控的实时诊断页面（按键码、修饰、事件类型、设备、解析结果，不泄露受保护文本）。
6. 参考源码（只看与问题相关部分）：https://github.com/pqrs-org/Karabiner-Elements 、https://github.com/Wunderlandmedia/HotkeyClash 、https://github.com/PerpetualBeta/ShortcutHUD 、https://github.com/obra/swift-macos-tap-detection 、https://github.com/nicholaspsmith/HotkeyKit 、https://github.com/kotique123/FnKeyboard 、https://github.com/keycastr/keycastr 。

验收矩阵：单独字母/数字/标点、数字小键盘、Shift+字母/数字、Cmd+数字、Ctrl+Shift、Option、Fn/Globe、F 键、媒体键、左右修饰键、Caps Lock、按住/重复、键盘布局与输入法切换、重映射、受保护输入、撤销/重新授权；用自动化测试验证模型/事件聚合，再列明实机 Magic Keyboard 尚需验证的差异。

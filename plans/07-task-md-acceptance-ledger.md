# Nexus task.md implementation and acceptance ledger

Source of truth: [task.md](../task.md), now **1,750 lines**. The first 1,450 lines cover Finder, Services, input statistics, iCloud Drive statistics backups, qsseda.com API and unified operation metadata. On 2026-11-21, `main` appended **300 lines** (lines 1451–1750) requesting a Paste-style clipboard shelf with local image/text/file previews, optional CloudKit synchronization and future iPhone/iPad clients. This branch incorporates that appended source specification. The earlier 1,450-line-only claim that iOS/CloudKit were not required must not be applied to the new full specification.

## New Paste-style requirements from lines 1451–1750 (not yet accepted)

- [x] **Architecture, SQLite metadata, clipboard change observation, floating cards, opt-in file/text capture, search, pinning and permanent named collections:** source code exists in the stacked PRs. PR #17 extends the search to all retained database rows. Final macOS UI/device acceptance is pending.
- [x] **Opt-in local screenshot/image payload and preview source implementation (PR #18):** independently disabled by default, up to 8 MiB of original approved image data with ImageIO-created bounded JPEG thumbnail, literal pasteboard format, SHA-256 storage sharing, foreign-key cascade cleanup on last reference, and user-controlled retention. On capture failure or oversize only metadata is recorded. SwiftUI loads thumbnail data lazily and original image is available for copy-again. Unit tests are included; full PR #18 CI and real pasteboard/thumbnail/AX acceptance must be verified before marking end-to-end complete.
- [x] **Opt-in local file thumbnail source (PR #19):** the floating card can request Quick Look thumbnails for one supported regular file (image/PDF/document/video) only after a separate user toggle. Metadata gate skips symlinks, packages, unknown/large files above 24 MiB, cloud-only iCloud items and general CloudStorage File Provider folders. The UI is lazy and preserves the icon fallback, and the generator returns bounded PNG bytes. Unit tests cover local, symlink, directory, size and cloud-path gates. CI and real macOS file-provider/thumbnail checks are still pending.
- [x] **Native permanent-collection card drag/reorder (PR #22):** selected collection cards export only opaque operation IDs via NSItemProvider; drops are accepted only if both source and target are existing members of that collection, then reuse the existing transaction-backed `moveOperation` persistence and reload the saved order. Reordering without a selected collection is disabled. SwiftUI/drag physical behavior remains to be verified after CI.
- [x] **Post-commit live clipboard shelf refresh (PR #21):** the existing passive monitor publishes only a monotonically increasing revision after a successful SQLite write on its utility queue. The shelf reacts to this revision to refresh card state without a second pasteboard observer or a polling timer. No clipboard text/image payload is included in notifications. macOS UI and CI acceptance still pending.
- [x] **Offline link and code card classification (PR #20):** already-authorized plain text is classified locally into standalone HTTP(S) URLs (hostname-only label) or explicit Markdown-fenced code (monospaced card). Credentials in URLs, script schemes and ordinary typing are never guessed to be links/code; no remote URL fetching, new clipboard capture or body transformation occurs. Regression tests cover CJK text, dangerous schemes and malformed language labels. Full CI and real UI acceptance remain pending.
- [x] **Safe locally persistent RTF typography (PR #32):** after a separate opt-in (also requiring text capture), bounded macOS RTF is decoded to plain text and sanitized UTF-16 spans carrying only bold/italic/underline flags. Raw RTF/HTML, attachments, links, remote resources and font data are not persisted. A separate SQLite table with foreign-key cleanup supports lazy styled cards across restarts, with plain text fallback. Includes UTF-16, size, durability, cleanup and native RTF parser tests. Device-level rich text appearance still requires visual acceptance.
- [x] **Offline safe HTML typography subset (PR #39):** under the existing, separately opted-in rich-text capture toggle, a bounded pure-Foundation parser recognizes only nested b/strong/i/em/u, span, p/div, br and a small set of safe entities. It rejects attributes, unknown elements, scripts, images and external resources without invoking WebKit/network; a plain-text match is required before a sanitized style run is saved in the same cascade-deleted SQLite table used for RTF. Unit tests cover CJK UTF-16 styling, nesting, named/numeric entities, malformed input and payload limits. CI/macOS visual acceptance pending.
- [ ] **Advanced previews:** faithful arbitrary HTML rendering, remote webpage titles, full code syntax highlighting and advanced File Provider previews remain unimplemented. Existing link/code icons and bounded RTF/HTML text styling are not equivalent to faithful webpage or binary previews.
- [x] **Best-effort foreground application attribution (PR #33):** the passive clipboard monitor now records the frontmost bundle identifier at detection time, never presenting it as a verified original writer. Cards resolve its installed application icon/name where available and explicitly label this as an unverified observation; unknown and externally reported sources stay distinct. File, text, image metadata, image payload and sanitized RTF copy records are covered. Tests assert accurate provenance labels; macOS clipboard cannot cryptographically verify the actual originating process.
- [x] **Quick paste race-safety implementation (PR #35):** after an explicit card selection, Nexus captures the clipboard change count before activating the previous app and declines synthetic Cmd+V if another copy modified the clipboard, the foreground process differs from the intended target, or AX permission was revoked. Control-click requests a plain-text paste when recognized; the context menu remains the fallback on systems that interpret Control-click as secondary-click. Core tests exercise all three rejection paths. This is still a paste **request**, not proof a third-party application accepted data.
- [ ] **Real quick-paste acceptance:** macOS Accessibility/Finder/third-party focus and app-specific successful paste must be physically verified on the user's Mac. Native file references work only if original URLs are valid.
- [x] **CloudKit-ready sync domain model (PR #23):** added provider-independent Codable operation/collection/membership records, stable record identities, monotonic logical revisions, deterministic conflict resolution, payload-free deletion tombstones, bounded batches, and independent metadata/text/name/path consents (disabled by default). Snapshot tests cover redaction, conflicting retries, deletion-before-stale-update, cross-device order and round-trip. **This is a tested schema/merge foundation, not an active CloudKit connection or completed sync.**
- [x] **Durable offline CloudKit change journal (PR #24):** separate SQLite WAL store for opt-in local edits, exact mutation-ID acknowledgements, tombstone persistence, remote replay/merge cache, bounded pending batches and atomic CKServerChangeToken bytes with applied remote pages. Crash/restart, update-during-upload, duplicate download pages, conflicting deletes, rollback and two-device convergence are covered by deterministic Core tests. It does **not** create or upload CKRecords, activate network access, or enable the service by default.
- [x] **Native CloudKit CKRecord codec (PR #27):** a strict, offline-only adapter serializes validated domain records to the versioned NexusClipboardChangeV1 record type in an explicit zone, checks the returned zone, ID, schema and envelope against its embedded JSON, rejects malformed/oversized data and preserves payload-free tombstones. Core/tests explicitly link Apple's CloudKit SDK. No iCloud login, zone creation, network calls, CloudKit entitlements or automatic upload is enabled.
- [x] **Consent-checked single-pass sync coordinator (PR #28):** an explicit-only actor coordinates bounded local outbox uploads, validates exact partial mutation acknowledgements, fetches one remote change-token page and checkpoints it transactionally with the merged records. Each attempt checks current user consent, including stale queued bodies/filenames/paths and collection names, before sending or accepting data; revoked consent prevents network transport calls for unauthorized pending changes. A transport protocol supports offline deterministic tests without an Apple account. **The CloudKit transport implementation, UI consent and live entitlement work are still absent.**
- [x] **CKDatabase private-zone transport source (PR #29):** actual Apple CloudKit SDK upload/download calls are now implemented behind the explicit `ClipboardCloudTransport` protocol, with private-database-only initialization and a separate user-invoked zone setup operation. Existing server records are fetched and compared by logical revision before optimistic change-tag updates; remote deletions must use durable tombstones. Downloads decode validated change pages and securely archive CKServerChangeToken checkpoints. This class is **not constructed or enabled by Nexus at launch**, and no iCloud entitlements or Apple account settings have been altered. CI compilation does not substitute for a signed user-account device integration test.
- [x] **Isolated opt-in macOS CloudKit settings/staging UI (PR #30):** explicit-only separate settings tab, independent body/name/path consent toggles, one-page-at-a-time bounded local history staging, durable collection-membership ordering snapshots, cloud zone creation button, manual single-pass network sync, cached remote metadata preview and authorized text copy-again. File/image bytes never leave the Mac; individual card deletions enqueue payload-free tombstones only after successful local deletion. The CloudKit container Info.plist key remains unset in all default builds, so unsigned CI and installed Nexus cannot upload. Signed app entitlement and real-account acceptance are externally gated. See docs/CLOUDKIT_TEST_SETUP.md.
- [x] **Fetch-before-upload convergence and explicit expired-token recovery (PR #34):** the coordinator now downloads and commits incremental remote changes before sending local mutations. It avoids a deadlock in which a newer server record would prevent the client from fetching the conflict resolution. It does not upload until the remote page backlog has been drained. A per-zone, user-invoked cursor reset replays zone changes after token expiration without deleting local cached records or pending edits. Swift/Core tests cover newer server revisions, duplicate pages, multi-page uploads and retained local pending state.
- [x] **Manual CloudKit cached-record restoration (PR #38):** privacy-checked, deterministic local-only mirror rows for cached cloud operations with idempotent replay and tombstones deleting only cloud mirrors; cloud paths never become pasteable local file references, and imported rows are excluded from outgoing synchronization queues. An explicit Settings button restores a bounded page from the offline CloudKit journal into regular SQLite history. Tests protect source UUIDs and avoid upload echo. Live account and signed multi-device acceptance still pending.
- [ ] **Actual CloudKit history sync:** Apple iCloud account permissions/entitlements, private database zone, durable change-token persistence, CKRecord upload/download, incremental change journal, deletion propagation/acknowledgement, asset transfer, background scheduling, conflict UX and offline retry remain to implement and validate. Current iCloud Drive statistics backup and qsseda.com metadata API are separate features.
- [x] **iPhone/iPadOS universal client source (PR #31):** separate XcodeGen project, adaptive SwiftUI application for both device families, user-tapped text clipboard import (no prohibited background reads), manual private CloudKit sync, local SQLite journal, cached history search/preview, explicit collection creation, membership, deletion tombstones and manual text copy-again. Shared CloudKit protocol/merge/codec/transport sources compile as a separate iOS framework. Adds dedicated unsigned iOS Simulator CI build. No Apple signing, real iPhone/iPad testing, image-asset sync, automatic pasteboard observation or production distribution is claimed; see Mobile/README.md.
- [x] **Drag history cards directly into named collections (PR #26):** every existing collection gets a visible native drop target; cards drag only opaque local operation UUIDs and the target validates the card is currently loaded and the destination is a known collection. The operation is added through the existing SQLite foreign-key-backed API with duplicate suppression, without copying raw clipboard payloads or modifying other collection order. Tests cover cross-collection isolation and rejected external IDs. CI and physical drag UX acceptance pending.
- [x] **Custom global clipboard shortcut editor (PR #25):** preserves existing opt-in Off/preset registrations and adds selectable physical letter/number/Space/F1–F12 keys plus Control/Option/Shift/Command modifiers (minimum two). Uses the existing Carbon RegisterEventHotKey conflict detection, rolls back to the prior working setting on registration failure, and persists a separately validated Codable custom configuration. Chinese/English settings and Core validation tests are included. Actual keyboard-layout/system conflict acceptance pending CI and Mac testing.
- [x] **Mouse-display safe floating-panel positioning (PR #36):** selects the mouse-containing NSScreen and now clamps the bottom panel's global-point rectangle inside its visible frame, including negative-origin external monitors, small windows and Retina scaling in logical points. The shelf reduces its minimum dimensions for compact screens. Pure geometry tests cover 640x480, side-mounted negative-origin and tall displays. Real multi-monitor/fullscreen visual testing is still required.
- [x] **Explicit incremental older-search paging (PR #37):** existing off-main, debounced SQL search now supports deterministic 200-item OFFSET pages, a Load Older control (at most 25 pages / 5,000 cards per request), and filter-change pagination resets. Lazy horizontal cards remain bounded; tests check stable order/no duplicates across 451 records.
- [ ] **Large-history search performance profiling:** full-text index design and real-device 100k+/multi-year latency benchmarking remain unverified. Deep OFFSET pages may degrade at very large scales.
- [ ] **Clipboard sensitivity:** some contradictory imperative phrases in task.md would collect sensitive/forbidden contents or remove retention settings. Preserve the safer existing defaults: no prohibited sensitive capture, no silent network transmission, independent opt-ins and user-accessible retention/delete controls.

## Remaining outside proven source-code implementation

- [ ] **macOS device acceptance:** native Finder/iCloud Drive (local, only-online), OneDrive, configured Mouser side keys, Fn/Globe/media/F21–F24 across HID models, Accessibility focus, multi-display, sleep/wake and >100GB packages.
- [ ] **Production cloud deployment:** a dedicated Nexus endpoint, isolated D1/SQLite storage, identity-specific authentication, token provisioning, safe rollback and live HTTPS origin are required. Existing `qsseda-work` / `qsseda-auth` deployments are unrelated and must not be overwritten.
- [ ] **OS-imposed limits:** a third-party application does not generally report completed paste or real originating clipboard app; Apple does not give apps a public API to force a single arbitrary third-party service into Finder's top-level menu. Only observed requests and documented service registration are possible. No fabricated statuses.
- [ ] **CloudKit records and iPhone/iPad clients:** now explicitly requested in the appended task.md lines 1451–1750, but remain unimplemented; iCloud Drive statistics backups/merges and authenticated qsseda API are separate existing modules, not substitutes for CloudKit.
- [ ] **Release safety:** real Apple Development signing, launch-at-login, legacy App Group and Finder Sync migration in an isolated test install; user has not asked to replace their currently installed version.

## Nonregression contract

Do not change installed apps, production signing credentials, original Bundle IDs or App Group contents. Do not bypass SIP/TCC, inject Finder, remap Mouser or synthesize a paste just to verify success. Do not record typed text/password fields, silently upload clipboard bodies, overwrite old databases, or treat an observed shortcut as proof of an operation.

No stage should be marked “finished” merely because a CI compilation succeeded; deployment, OS permission, visual UI behavior and unsupported APIs are separate evidence categories.

# Nexus task.md implementation and acceptance ledger

Source of truth: [task.md](../task.md), now **1,750 lines**. The first 1,450 lines cover Finder, Services, input statistics, iCloud Drive statistics backups, qsseda.com API and unified operation metadata. On 2026-11-21, `main` appended **300 lines** (lines 1451–1750) requesting a Paste-style clipboard shelf with local image/text/file previews, optional CloudKit synchronization and future iPhone/iPad clients. This branch incorporates that appended source specification. The earlier 1,450-line-only claim that iOS/CloudKit were not required must not be applied to the new full specification.

- [x] **Menu-bar clipboard pause/resume (PR #47):** the existing menu-bar popover now explicitly exposes the same persisted clipboard pause state as Privacy Settings. Pausing invalidates existing observation timers and resets observed pasteboard revision without collecting intervening data; resuming retains the user's separate text/image/file opt-ins. The menu's icon and accessible label reflect live pause state. CI/real login-session behavior still requires verification.
- [x] **Menu-bar quick history and pinned clipboard navigation (PR #46):** the existing menu popover now offers the five most recent and up to three pinned clipboard records from bounded local SQLite lookups on a utility queue. Menu items display short Unicode-safe metadata/plaintext labels and open the full clipboard shelf rather than synthesizing a paste or reading binary payloads. A lightweight revision and pin preference refresh these lists without another clipboard observer. macOS accessibility/UI acceptance pending.
- [x] **Configurable consecutive plain-text copy strategy (PR #45):** the default remains lossless Keep Every Copy; optional Refresh Latest performs an atomic SQLite match against the immediately preceding local clipboard event only, within ten minutes. Exact same plain-text content reuses the stable history UUID, refreshes observed foreground metadata and invalidates prior operation-network upload receipts; intervening file/image/RTF copies or older entries are not consolidated. Existing pins and permanent collection memberships survive. Tests verify preservation, source/time updates, type boundaries and resync correctness. The feature is independently configurable in privacy settings.
- [x] **Architecture, SQLite metadata, clipboard change observation, floating cards, opt-in file/text capture, search, pinning and permanent named collections:** source code exists in the stacked PRs. PR #17 extends the search to all retained database rows. Final macOS UI/device acceptance is pending.
- [x] **Opt-in local screenshot/image payload and preview source implementation (PR #18):** independently disabled by default, up to 8 MiB of original approved image data with ImageIO-created bounded JPEG thumbnail, literal pasteboard format, SHA-256 storage sharing, foreign-key cascade cleanup on last reference, and user-controlled retention. On capture failure or oversize only metadata is recorded. SwiftUI loads thumbnail data lazily and original image is available for copy-again. Unit tests are included; full PR #18 CI and real pasteboard/thumbnail/AX acceptance must be verified before marking end-to-end complete.
- [x] **Opt-in local file thumbnail source (PR #19):** the floating card can request Quick Look thumbnails for one supported regular file (image/PDF/document/video) only after a separate user toggle. Metadata gate skips symlinks, packages, unknown/large files above 24 MiB, cloud-only iCloud items and general CloudStorage File Provider folders. The UI is lazy and preserves the icon fallback, and the generator returns bounded PNG bytes. Unit tests cover local, symlink, directory, size and cloud-path gates. CI and real macOS file-provider/thumbnail checks are still pending.
- [x] **Native permanent-collection card drag/reorder (PR #22):** selected collection cards export only opaque operation IDs via NSItemProvider; drops are accepted only if both source and target are existing members of that collection, then reuse the existing transaction-backed `moveOperation` persistence and reload the saved order. Reordering without a selected collection is disabled. SwiftUI/drag physical behavior remains to be verified after CI.
- [x] **Post-commit live clipboard shelf refresh (PR #21):** the existing passive monitor publishes only a monotonically increasing revision after a successful SQLite write on its utility queue. The shelf reacts to this revision to refresh card state without a second pasteboard observer or a polling timer. No clipboard text/image payload is included in notifications. macOS UI and CI acceptance still pending.
- [x] **Offline link and code card classification (PR #20):** already-authorized plain text is classified locally into standalone HTTP(S) URLs (hostname-only label) or explicit Markdown-fenced code (monospaced card). Credentials in URLs, script schemes and ordinary typing are never guessed to be links/code; no remote URL fetching, new clipboard capture or body transformation occurs. Regression tests cover CJK text, dangerous schemes and malformed language labels. Full CI and real UI acceptance remain pending.
- [x] **Safe locally persistent RTF typography (PR #32):** after a separate opt-in (also requiring text capture), bounded macOS RTF is decoded to plain text and sanitized UTF-16 spans carrying only bold/italic/underline flags. Raw RTF/HTML, attachments, links, remote resources and font data are not persisted. A separate SQLite table with foreign-key cleanup supports lazy styled cards across restarts, with plain text fallback. Includes UTF-16, size, durability, cleanup and native RTF parser tests. Device-level rich text appearance still requires visual acceptance.
- [x] **Offline safe HTML typography subset (PR #39):** under the existing, separately opted-in rich-text capture toggle, a bounded pure-Foundation parser recognizes only nested b/strong/i/em/u, span, p/div, br and a small set of safe entities. It rejects attributes, unknown elements, scripts, images and external resources without invoking WebKit/network; a plain-text match is required before a sanitized style run is saved in the same cascade-deleted SQLite table used for RTF. Unit tests cover CJK UTF-16 styling, nesting, named/numeric entities, malformed input and payload limits. CI/macOS visual acceptance pending.
- [x] **Bounded offline code highlighting (PR #40):** explicitly Markdown-fenced Swift, Python, JavaScript/TypeScript, JSON and shell source receives lazy, local-only keyword, string, numeric and comment colors in a monospaced card. The clipboard body is not modified; lexer stops at 16 KiB input or 256 tokens and does not evaluate code, guess unfenced languages or load external grammars. Core tests include Unicode UTF-16 ranges, supported languages, unrecognized fences and token budgets. macOS visual accessibility remains unverified.

- [x] **Per-card accent color markers (PR #43):** existing clipboard cards can be assigned an allowlisted system color from their native context menu; chosen colors are separate from automatic type/URL accent colors. SQLite schema v5 stores only the color tag with foreign-key cascade cleanup on history deletion. Cards load tags in bounded off-main batches, and an accessible labeled marker supplements the color itself. Tests cover restart durability, reset to automatic, invalid values and deletion cleanup. File, text, image metadata, image payload and sanitized RTF copy records are covered. - [x] **Quick paste race-safety implementation (PR #35):** after an explicit card selection, Nexus captures the clipboard change count before activating the previous app and declines synthetic Cmd+V if another copy modified the clipboard, the foreground process differs from the intended target, or AX permission was revoked. - [x] **Fetch-before-upload convergence and explicit expired-token recovery (PR #34):** the coordinator now downloads and commits incremental remote changes before sending local mutations. ## Remaining outside proven source-code implementation

- [ ] **macOS device acceptance:** native Finder/iCloud Drive (local, only-online), OneDrive, configured Mouser side keys, Fn/Globe/media/F21–F24 across HID models, Accessibility focus, multi-display, sleep/wake and >100GB packages.
- [ ] **Production cloud deployment:** a dedicated Nexus endpoint, isolated D1/SQLite storage, identity-specific authentication, token provisioning, safe rollback and live HTTPS origin are required. Existing `qsseda-work` / `qsseda-auth` deployments are unrelated and must not be overwritten.
- [ ] **OS-imposed limits:** a third-party application does not generally report completed paste or real originating clipboard app; Apple does not give apps a public API to force a single arbitrary third-party service into Finder's top-level menu. Only observed requests and documented service registration are possible. No fabricated statuses.
- [x] **CloudKit domain and universal iPhone/iPad client source:** the appended P2 work now has versioned CKRecord codec, private-zone transport, SQLite change journal, manual opt-in Mac/iOS controller, and bilingual universal iOS app with independent offline clipboard text history. macOS and unsigned iOS Simulator build coverage is present. Real provisioned iOS builds, authenticated CloudKit cross-device sync and binary asset fidelity are separate pending verification/release gates.
- [ ] **Release safety:** real Apple Development signing, launch-at-login, legacy App Group and Finder Sync migration in an isolated test install; user has not asked to replace their currently installed version.

## Nonregression contract

Do not change installed apps, production signing credentials, original Bundle IDs or App Group contents. Do not bypass SIP/TCC, inject Finder, remap Mouser or synthesize a paste just to verify success. Do not record typed text/password fields, silently upload clipboard bodies, overwrite old databases, or treat an observed shortcut as proof of an operation.

No stage should be marked “finished” merely because a CI compilation succeeded; deployment, OS permission, visual UI behavior and unsupported APIs are separate evidence categories.
